1.1 Convolution from Scratch

  1. Convolution is one of the basic operations used throughout image processing. It transforms an image by moving a small filter kernel across the image and computing a weighted combination of nearby pixel values. Different kernels therefore allow the same computational operation to perform very different types of image processing.

    Let \(I\) denote an image and \(K\) denote a filter kernel. The filtered image can be written as

    \[ \boxed{ (I*K)[m,n] = \sum_{i} \sum_{j} K[i,j] I[m-i,n-j] } \]

    Each output pixel is produced from a local neighborhood of the original image. The kernel determines how strongly each neighboring pixel contributes to the result.

    \[ \boxed{ \text{Input Image} \longrightarrow \text{Local Neighborhood} \longrightarrow \text{Weighted Sum} \longrightarrow \text{Output Pixel} } \]

    As a first example, I use a \(9\times9\) box filter. Every entry in the kernel has the same weight, so each output pixel becomes the average of a local \(9\times9\) neighborhood.

    \[ \boxed{ K_{\mathrm{box}} = \frac{1}{81} \mathbf 1_{9\times9} } \]

    Averaging nearby pixels suppresses rapid local intensity changes. The resulting image therefore appears smoother and contains less fine detail.

    I implemented convolution from scratch in two different ways. The first implementation uses four explicit loops. The outer two loops visit every output pixel, while the inner two loops traverse the filter window and accumulate the weighted pixel values.

    \[ \boxed{ \text{Image Rows} \times \text{Image Columns} \times \text{Kernel Rows} \times \text{Kernel Columns} } \]

    The second implementation keeps the two outer loops over output pixels but replaces the two inner loops with NumPy array operations. For each output location, the corresponding image patch is multiplied with the kernel and summed using vectorized computation.

    \[ \boxed{ I_{\mathrm{patch}} \odot K \longrightarrow \operatorname{sum} \longrightarrow I_{\mathrm{out}}[m,n] } \]

    In both implementations, I use zero padding around the image boundary. Without padding, the kernel cannot be centered on pixels close to the image border and the output image would become smaller. Padding preserves the original spatial dimensions.

    \[ \boxed{ H\times W \longrightarrow \text{Zero Padding} \longrightarrow \text{Convolution} \longrightarrow H\times W } \]

    I apply both implementations to the same selfie using the \(9\times9\) box filter. The two implementations produce the same smoothing result.

  4. Although the three implementations produce the same filtered image, their computational costs are very different. The four loop version performs nearly all operations through explicit Python iteration and is therefore the slowest. The two loop version uses NumPy to perform the kernel computation more efficiently. The SciPy implementation is substantially more optimized and achieves the shortest runtime in this experiment.

    \[ \boxed{ T_{\mathrm{four\ loops}} > T_{\mathrm{two\ loops}} > T_{\mathrm{SciPy}} } \]
    runtime.png

    This comparison illustrates an important distinction between the mathematical definition of an image operation and its computational implementation. All three methods implement the same filtering idea, while vectorization and optimized numerical routines make the computation much more efficient.

  5. The box filter demonstrates that changing the kernel changes the behavior of convolution. I next replace the averaging kernel with finite difference filters.

    \[ \boxed{ D_x = \begin{bmatrix} 1 & 0 & -1 \end{bmatrix} } \]
    \[ \boxed{ D_y = \begin{bmatrix} 1\\ 0\\ -1 \end{bmatrix} } \]

    Instead of averaging neighboring intensities, these filters measure local intensity change. Convolution with \(D_x\) measures horizontal intensity variation, while convolution with \(D_y\) measures vertical intensity variation.

    \[ \boxed{ I_x = I*D_x, \qquad I_y = I*D_y } \]

    Regions with little intensity variation produce values close to zero. Strong transitions produce responses with larger magnitude. This makes finite difference filters useful for detecting image structure such as edges.

    selfie_Dx.png
    selfie_Dy.png

  6. This section establishes convolution as a general framework for image filtering. The same operation can smooth an image or measure local image derivatives simply by changing the kernel.

    \[ \boxed{ \begin{aligned} \text{Box Kernel} &\longrightarrow \text{Local Averaging} \longrightarrow \text{Smoothing} \\ D_x,\ D_y &\longrightarrow \text{Local Differences} \longrightarrow \text{Image Derivatives} \end{aligned} } \]

    The finite difference responses provide the horizontal and vertical components of the image gradient. In the next section, I combine these components to measure edge strength and construct a binary edge map.

1.2 Finite Differences and Edge Detection

  1. After using finite difference filters in the previous section, I apply them to the Cameraman image to construct an edge map. The central idea is that an edge corresponds to a rapid change in image intensity. Image derivatives provide a direct way to measure these changes.

    The original grayscale image is shown below.

    cameraman.png

    I first convolve the image with the horizontal and vertical finite difference operators introduced in Part 1.1.

    \[ D_x = \begin{bmatrix} 1 & 0 & -1 \end{bmatrix}, \qquad D_y = \begin{bmatrix} 1\\ 0\\ -1 \end{bmatrix} \]

    These filters approximate the partial derivatives of the image along the horizontal and vertical directions.

    \[ \boxed{ I_x = I*D_x, \qquad I_y = I*D_y } \]

    The horizontal derivative \(I_x\) responds strongly where intensity changes rapidly as we move across image columns. The vertical derivative \(I_y\) responds strongly where intensity changes rapidly as we move across image rows.

    Together, these two derivative images describe the local image gradient.

    \[ \boxed{ \nabla I = \begin{bmatrix} I_x\\ I_y \end{bmatrix} } \]
    cameraman_Dx.png
    cameraman_Dy.png

  2. The two derivative components can be combined into a single measure of how strongly the image changes at every pixel. This quantity is the gradient magnitude.

    \[ \boxed{ \left\| \nabla I \right\| = \sqrt{ I_x^2 + I_y^2 } } \]

    A small gradient magnitude indicates that the local image intensity changes slowly. A large gradient magnitude indicates a strong local transition and is therefore evidence of an edge.

    \[ \boxed{ \begin{aligned} \left\| \nabla I \right\| \text{ small} &\longrightarrow \text{Smooth Region} \\ \left\| \nabla I \right\| \text{ large} &\longrightarrow \text{Strong Edge} \end{aligned} } \]

    The gradient also has an orientation given by

    \[ \theta = \operatorname{atan2} \left( I_y, I_x \right) \]

    This direction indicates the direction of the fastest increase in image intensity. For this part of the project, I only need the gradient magnitude because the goal is to measure edge strength rather than edge orientation.

    cameraman_grad_mag.png

  3. The gradient magnitude is still a continuous valued image. To obtain a binary edge map, I apply a threshold that separates strong gradient responses from weak ones.

    \[ \boxed{ E(x,y) = \begin{cases} 255, & \left\| \nabla I(x,y) \right\| \geq \tau \\ 0, & \left\| \nabla I(x,y) \right\| < \tau \end{cases} } \]

    The choice of threshold controls the tradeoff between retaining weak edges and suppressing small responses. A very low threshold keeps many weak gradients, including responses caused by noise and texture. A very high threshold removes noise more aggressively but may also discard meaningful edges.

    I found that a threshold of \(35\) provides a reasonable balance for this image. Strong object boundaries are preserved while many weaker responses are removed.

    \[ \boxed{ \tau = 35 } \]
    cameraman_binarized.png

  4. The complete edge detection procedure can therefore be summarized as

    \[ \boxed{ \text{Image} \longrightarrow D_x,\ D_y \longrightarrow I_x,\ I_y \longrightarrow \left\| \nabla I \right\| \longrightarrow \text{Threshold} \longrightarrow \text{Binary Edge Map} } \]

    One limitation becomes visible in this process. Finite difference filters respond to rapid intensity changes, but image noise also consists largely of rapid local variations. Derivative filters can therefore amplify noise together with real edges.

    The next section addresses this problem by smoothing the image with a Gaussian before differentiation. It also shows that smoothing followed by differentiation can be combined into a single Derivative of Gaussian filter through the algebraic properties of convolution.

1.3 Derivative of Gaussian

  1. In the previous section, finite difference filters were used to detect image edges from local intensity changes. However, these derivative filters also respond strongly to small high frequency variations caused by image noise. This can introduce many weak and unstable responses into the edge map.

    To make the derivative estimate more robust, I first smooth the image using a Gaussian filter. Gaussian filtering averages nearby pixels with smoothly decaying weights, which suppresses high frequency noise while preserving larger image structures.

    \[ \boxed{ I_{\mathrm{smooth}} = I * G } \]

    After smoothing, I apply the finite difference filters to the Gaussian filtered image.

    \[ \boxed{ I_x = (I*G)*D_x } \]
    \[ \boxed{ I_y = (I*G)*D_y } \]

    The horizontal and vertical derivative responses can then be combined using the same gradient magnitude computation as in the previous section.

    \[ \boxed{ \left\| \nabla I \right\| = \sqrt{ I_x^2 + I_y^2 } } \]

    Because the image is smoothed before differentiation, small noisy variations are reduced before the derivative filters are applied. The resulting edge map is therefore cleaner and emphasizes larger, more stable image boundaries.

    Gaussian smoothing followed by differentiation

  2. The same operation can also be performed in a single filtering step. Convolution is associative, which means that the order in which consecutive filters are grouped does not change the final result.

    \[ \boxed{ (I*G)*D_x = I*(G*D_x) } \]
    \[ \boxed{ (I*G)*D_y = I*(G*D_y) } \]

    Instead of first smoothing the image and then differentiating it, I can therefore differentiate the Gaussian filter itself.

    \[ \boxed{ G_x = G*D_x, \qquad G_y = G*D_y } \]

    These filters are Derivative of Gaussian filters. They combine smoothing and differentiation into a single kernel.

    \[ \boxed{ I_x = I*G_x, \qquad I_y = I*G_y } \]

    The result is mathematically equivalent to first applying the Gaussian filter and then applying the finite difference operator. The difference is that the two filtering operations have been combined before being applied to the image.

    \[ \boxed{ \text{Smooth Then Differentiate} = \text{Differentiate the Gaussian Then Filter} } \]
    Derivative of Gaussian result

  3. The two approaches produce the same result because they represent the same sequence of linear filtering operations. The difference lies only in when the filters are combined.

    \[ \boxed{ \begin{aligned} \text{Two Step Method} &\qquad I \longrightarrow I*G \longrightarrow (I*G)*D \\ \text{One Step Method} &\qquad G*D \longrightarrow I*(G*D) \end{aligned} } \]

    This example illustrates an important property of convolution. Multiple linear filters can often be combined into a single filter before being applied to the image. This allows us to understand image processing operations not only as sequences of steps, but also as combinations of kernels.

    It also introduces a frequency based interpretation that becomes important in the next part of the project. Gaussian smoothing suppresses high frequency components, while image derivatives emphasize rapid intensity changes. Combining the two produces a derivative operator that is less sensitive to high frequency noise.

    \[ \boxed{ \text{Gaussian Smoothing} \longrightarrow \text{Noise Suppression} \longrightarrow \text{Differentiation} \longrightarrow \text{Cleaner Edge Response} } \]
