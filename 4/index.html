1.1 Image Capture

The first step is to capture a set of overlapping images that can later be aligned through projective transformations. I collected two image sequences, one inside my room and one inside the library. Each sequence contains three images observing the same scene from different viewing directions.

While capturing the images, I kept the camera position approximately fixed and mainly rotated the camera to change the viewing direction. This condition is important because images taken from the same center of projection can be related through a homography.

\[ \boxed{ \mathbf p' \sim H\mathbf p } \]

Here, \(\mathbf p\) and \(\mathbf p'\) represent corresponding image points in two different views, while \(H\) is a \(3\times3\) projective transformation. The symbol \(\sim\) indicates equality up to an arbitrary scale in homogeneous coordinates.

The reason this works can be understood geometrically. Rotating the camera changes the orientation of the image plane while keeping the optical center approximately unchanged. The incoming scene rays therefore remain associated with the same center of projection and are simply reparameterized on different image planes. A homography can describe this image to image mapping.

\[ \boxed{ \text{Fixed Camera Center} \quad + \quad \text{Camera Rotation} \quad \Longrightarrow \quad \text{Homography Between Views} } \]

Keeping the camera center approximately fixed also reduces parallax. If the camera were translated significantly, nearby and distant objects would move by different amounts across the images. In that case, a single global homography would generally no longer align the entire three dimensional scene.

I also ensured that neighboring images contain substantial overlap. The overlapping regions provide corresponding visual structures that will later be used to estimate the homographies between views. In Part A, these correspondences are selected manually. In Part B, the same task will be performed automatically using feature detection and matching.

1.2 Recovering the Homography

  1. Once two images contain overlapping content, the next step is to determine the projective transformation that maps coordinates from one image into the other. This transformation is represented by a homography matrix \(H\).

    A homography is not itself a three dimensional rotation matrix. Instead, it is a two dimensional projective transformation between two image planes. In the panorama setting used here, however, its origin can be understood directly from the underlying camera rotation.

    Consider a pixel in the first image written in homogeneous coordinates.

    \[ \mathbf p_1 = \begin{bmatrix} u_1\\ v_1\\ 1 \end{bmatrix} \]

    Using the intrinsic matrix of the first camera, this pixel can be back projected into a three dimensional viewing direction in the first camera coordinate system.

    \[ \boxed{ \mathbf d_1 \propto K_1^{-1}\mathbf p_1 } \]

    During panorama capture, the camera center remains approximately fixed while the camera rotates. Let \(R\) denote the relative rotation from the first camera orientation to the second. The same viewing ray expressed in the second camera coordinate system is therefore

    \[ \boxed{ \mathbf d_2 = R\mathbf d_1 } \]

    Projecting this direction onto the second image plane using the second intrinsic matrix gives

    \[ \mathbf p_2 \sim K_2\mathbf d_2 \]

    Substituting the previous expressions gives

    \[ \mathbf p_2 \sim K_2 R K_1^{-1} \mathbf p_1 \]

    This means that pure camera rotation induces a single projective mapping between the two image planes. We define this mapping as the homography

    \[ \boxed{ H = K_2 R K_1^{-1} } \]

    If both images are captured using the same camera with unchanged zoom and focal settings, then the two intrinsic matrices are the same and the expression becomes

    \[ \boxed{ H = KRK^{-1} } \]

    This explains why the images collected in Part 1.1 can be aligned using a single homography. The three dimensional camera rotation induces a two dimensional projective transformation on the image coordinates.

    The same homography model also applies when the observed scene is planar, even if the camera center changes. For a general three dimensional scene with significant camera translation, however, different depths produce different parallax and one global homography is generally insufficient.

    In this project, we do not explicitly calibrate the camera or recover the relative rotation \(R\). Instead, we observe corresponding points directly in the two images and estimate the equivalent image to image transformation \(H\) from those correspondences.

    \[ \boxed{ \mathbf p_i \longleftrightarrow \mathbf p_i' \qquad \Longrightarrow \qquad \mathbf p_i' \sim H\mathbf p_i } \]

    Image coordinates are written in homogeneous form.

    \[ \mathbf p = \begin{bmatrix} x\\ y\\ 1 \end{bmatrix}, \qquad \mathbf p' = \begin{bmatrix} x'\\ y'\\ 1 \end{bmatrix} \]

    The homography maps the first point to the corresponding point in the second image up to a nonzero scale.

    \[ \boxed{ \mathbf p' \sim H\mathbf p } \]

    The matrix \(H\) has the form

    \[ H = \begin{bmatrix} h_{11} & h_{12} & h_{13}\\ h_{21} & h_{22} & h_{23}\\ h_{31} & h_{32} & h_{33} \end{bmatrix} \]

    Although the matrix contains nine entries, multiplying the entire matrix by any nonzero scalar produces exactly the same projective mapping. The homography therefore contains eight independent degrees of freedom.

    \[ \boxed{ H \sim \lambda H } \]

    To see how the matrix changes image coordinates, we first multiply \(H\) by the homogeneous source point.

    \[ H\mathbf p = \begin{bmatrix} h_{11}x+h_{12}y+h_{13}\\ h_{21}x+h_{22}y+h_{23}\\ h_{31}x+h_{32}y+h_{33} \end{bmatrix} \]

    The result is still expressed in homogeneous coordinates. Dividing by its third component converts it back into ordinary pixel coordinates.

    \[ \boxed{ x' = \frac{ h_{11}x+h_{12}y+h_{13} }{ h_{31}x+h_{32}y+h_{33} } } \]
    \[ \boxed{ y' = \frac{ h_{21}x+h_{22}y+h_{23} }{ h_{31}x+h_{32}y+h_{33} } } \]

    The first two rows determine the transformed horizontal and vertical coordinates. The third row produces a position dependent homogeneous scale. This final division is what allows a homography to represent perspective effects that cannot be described by an affine transformation.

    Multiplying both equations by their common denominator removes the fractions.

    \[ x' \left( h_{31}x+h_{32}y+h_{33} \right) = h_{11}x+h_{12}y+h_{13} \]
    \[ y' \left( h_{31}x+h_{32}y+h_{33} \right) = h_{21}x+h_{22}y+h_{23} \]

    The important observation is that the image coordinates \(x,y,x',y'\) are already known from the selected correspondences. The only unknown quantities are the entries of \(H\). After rearranging the equations, each correspondence therefore provides two linear constraints on the homography parameters.

    The unknown entries of \(H\) can be collected into a single vector.

    \[ \mathbf h = \begin{bmatrix} h_{11} & h_{12} & h_{13} & h_{21} & h_{22} & h_{23} & h_{31} & h_{32} & h_{33} \end{bmatrix}^{T} \]

    Each point correspondence contributes two linear constraints on \(\mathbf h\). One convenient form is

    \[ \begin{bmatrix} -x & -y & -1 & 0 & 0 & 0 & xx' & yx' & x'\\ 0 & 0 & 0 & -x & -y & -1 & xy' & yy' & y' \end{bmatrix} \mathbf h = \mathbf 0 \]

    Stacking the constraints from all correspondences produces a homogeneous linear system.

    \[ \boxed{ A\mathbf h = \mathbf 0 } \]

    Since the homography contains eight independent degrees of freedom and each correspondence provides two independent constraints, at least four point correspondences are required. These points should not form a degenerate configuration such as all lying on the same line.

    \[ \boxed{ 4 \text{ correspondences} \times 2 \text{ constraints} = 8 \text{ constraints} } \]

    In practice, more than four correspondences are preferable. This produces an overdetermined system and allows the estimated homography to average over small inaccuracies in manually selected points.

    Before solving for the homography, I normalize the image coordinates. The points are translated and scaled so that their numerical ranges are better conditioned. Let \(T\) and \(T'\) denote the normalization transformations for the source and destination points.

    \[ \tilde{\mathbf p} = T\mathbf p, \qquad \tilde{\mathbf p}' = T'\mathbf p' \]

    I then construct the linear system from the normalized coordinates and solve it using Singular Value Decomposition. Since we seek a nonzero vector satisfying \(A\mathbf h\approx\mathbf 0\), the solution is the right singular vector associated with the smallest singular value of \(A\).

    \[ A = U\Sigma V^T \]
    \[ \boxed{ \tilde{\mathbf h} = \mathbf v_{\min} } \]

    After reshaping this vector into the normalized homography \(\tilde H\), I transform it back into the original pixel coordinate systems.

    \[ \boxed{ H = T'^{-1} \tilde H T } \]

    Finally, I remove the arbitrary projective scale by normalizing the matrix so that \(h_{33}=1\) whenever this value is nonzero.

    \[ \boxed{ H \leftarrow \frac{H}{H_{33}} } \]

1.3 Inverse Warping and Interpolation

  1. After recovering the homography, the next step is to use it to resample one image into the coordinate system of another. If \(H\) maps a source point \(\mathbf p\) to a destination point \(\mathbf p'\), then

    \[ \boxed{ \mathbf p' \sim H\mathbf p } \]

    A direct approach would be to send every source pixel forward through this transformation. However, the transformed coordinates generally do not land exactly on the integer pixel grid of the destination image. Some destination pixels may receive multiple source samples, while others may receive none. This can produce visible holes in the warped result.

    I therefore use inverse warping. Instead of pushing source pixels into the destination, I visit each destination pixel and determine where its color should come from in the source image.

    \[ \boxed{ \mathbf p \sim H^{-1}\mathbf p' } \]

    For a destination pixel \(\mathbf p'=[x',y',1]^T\), the inverse homography first gives a homogeneous source coordinate

    \[ \begin{bmatrix} \tilde x\\ \tilde y\\ \tilde w \end{bmatrix} = H^{-1} \begin{bmatrix} x'\\ y'\\ 1 \end{bmatrix} \]

    Dividing by the final homogeneous component recovers the corresponding source image location.

    \[ \boxed{ x=\frac{\tilde x}{\tilde w}, \qquad y=\frac{\tilde y}{\tilde w} } \]

    To evaluate the warping procedure, I use two different source images and map both toward the same reference geometry. The first source and the reference image are shown below.

    source1
    reference.png

    Inverse warping solves the geometric correspondence problem, but it introduces a second issue. The recovered source location \((x,y)\) is usually continuous rather than integer valued. Since the source image only stores colors at discrete pixel locations, we need interpolation to estimate the color at the requested coordinate.

    I compare Nearest Neighbor Interpolation and Bilinear Interpolation.

    Nearest Neighbor Interpolation

    Nearest Neighbor simply uses the color of the closest source pixel.

    \[ \boxed{ I(x,y) \approx I \left( \operatorname{round}(x), \operatorname{round}(y) \right) } \]

    This method is fast because only one source pixel needs to be accessed. However, the selected value changes abruptly as the sampling coordinate crosses pixel boundaries, which can make the warped image appear more blocky or jagged.

    Bilinear Interpolation

    Bilinear Interpolation instead combines the four neighboring source pixels. If the continuous coordinate lies inside the pixel cell defined by \((x_0,y_0)\), \((x_1,y_0)\), \((x_0,y_1)\), and \((x_1,y_1)\), I define

    \[ a=x-x_0, \qquad b=y-y_0 \]

    and compute the interpolated color using

    \[ \boxed{ \begin{aligned} I(x,y) ={}& (1-a)(1-b)I(x_0,y_0) + a(1-b)I(x_1,y_0) \\ &+ (1-a)bI(x_0,y_1) + abI(x_1,y_1) \end{aligned} } \]

    Nearby pixels receive larger weights, so the sampled color varies smoothly as the continuous coordinate moves across the source image.

    The complete warping procedure can therefore be viewed as a sequence of geometric mapping followed by image resampling.

    \[ \boxed{ \text{Destination Pixel} \longrightarrow H^{-1} \longrightarrow \text{Source Coordinate} \longrightarrow \text{Interpolation} \longrightarrow \text{Warped Color} } \]

    With this procedure implemented, images can now be warped into a shared coordinate system. The remaining step is to combine their overlapping regions smoothly to form a panorama.

2.1 Harris Corner Detection and ANMS

  1. In Part A, the homography between two images was estimated from manually selected point correspondences. This works well when only a few image pairs are involved, but manual selection becomes impractical when the number of images increases. Part B therefore replaces this manual step with an automatic feature matching pipeline.

    \[ \boxed{ \text{Images} \longrightarrow \text{Feature Detection} \longrightarrow \text{Feature Description} \longrightarrow \text{Feature Matching} \longrightarrow \text{Homography} } \]

    The first task is to identify image locations that can be recognized reliably across different views. Flat regions are poor choices because nearby pixels have very similar appearance. Edges are also ambiguous because movement along the edge produces little visual change. Corners are much more distinctive because shifting a small window in almost any direction produces a noticeable change in intensity.

    \[ \boxed{ \begin{aligned} \text{Flat Region} &\quad \text{small change in all directions} \\ \text{Edge} &\quad \text{small change along one direction} \\ \text{Corner} &\quad \text{large change in multiple directions} \end{aligned} } \]

    I use the Harris Corner Detector to measure this behavior. For a small image window \(W\), Harris considers how much the window changes when shifted by a small displacement \((u,v)\).

    \[ E(u,v) = \sum_{(x,y)\in W} \left[ I(x+u,y+v) - I(x,y) \right]^2 \]

    A corner should produce a large value of \(E(u,v)\) for many small displacement directions. Using a first order approximation of the image intensity, this expression can be written approximately as a quadratic form.

    \[ \boxed{ E(u,v) \approx \begin{bmatrix} u & v \end{bmatrix} M \begin{bmatrix} u\\ v \end{bmatrix} } \]

    The matrix \(M\) is the second moment matrix computed from local image gradients.

    \[ \boxed{ M = \sum_{(x,y)\in W} \begin{bmatrix} I_x^2 & I_xI_y\\ I_xI_y & I_y^2 \end{bmatrix} } \]

    The two eigenvalues of \(M\) describe how strongly the image changes along two principal directions. If both eigenvalues are small, the region is approximately flat. If one is large and the other is small, the region behaves like an edge. If both are large, the location behaves like a corner.

    \[ \boxed{ \begin{aligned} \lambda_1 \approx 0,\, \lambda_2 \approx 0 &\quad \Longrightarrow \quad \text{Flat} \\ \lambda_1 \gg \lambda_2 \text{ or } \lambda_2 \gg \lambda_1 &\quad \Longrightarrow \quad \text{Edge} \\ \lambda_1,\lambda_2 \text{ both large} &\quad \Longrightarrow \quad \text{Corner} \end{aligned} } \]

    Rather than explicitly thresholding both eigenvalues, Harris combines them into a scalar corner response.

    \[ \boxed{ R = \det(M) - k \operatorname{trace}(M)^2 } \]

    Locations with large positive \(R\) are strong corner candidates. After computing the response over the image, I retain strong local maxima as candidate feature points.

  2. Harris Corner Detection usually produces far more points than are needed for matching. It can also produce many strong responses in a small textured region, while leaving other parts of the image poorly represented. Using all of these points would increase computation without necessarily improving alignment.

    I therefore apply Adaptive Non Maximal Suppression to select a smaller and more spatially distributed set of features. The goal is not simply to keep the strongest Harris responses. Instead, ANMS favors points that remain locally dominant over a large spatial region.

    For each Harris candidate \(i\), we can associate a suppression radius \(r_i\). Conceptually, this radius measures how far we must move from feature \(i\) before encountering another feature with a sufficiently stronger Harris response.

    \[ \boxed{ r_i = \min_j \left\| \mathbf x_i - \mathbf x_j \right\|_2 } \]

    The minimization is performed over points \(j\) whose Harris response is sufficiently stronger than the response at point \(i\). A large suppression radius therefore means that the feature is a strong representative of a relatively large surrounding region.

    I rank the Harris candidates according to their suppression radii and retain the 500 points with the largest values. This produces a fixed number of features while encouraging them to cover the image more evenly.

    \[ \boxed{ \text{Dense Harris Candidates} \longrightarrow \text{ANMS} \longrightarrow 500 \text{ Spatially Distributed Features} } \]

    The following comparisons show the detected corners before and after ANMS. Red points indicate the selected feature locations. The full Harris detector produces many densely clustered candidates, while ANMS retains a smaller set that better covers the scene.

    \[ \boxed{ \text{Harris} \longrightarrow \text{Where Are Distinctive Corners} \longrightarrow \text{ANMS} \longrightarrow \text{Which Corners Should Be Kept} } \]

    At this stage, each image has a compact set of well distributed feature locations. The next step is to describe the local appearance around every selected point so that corresponding features can be compared across different images.

  1. In this section, I compute the final homography matrix using RANSAC. First, I randomly select four pairs of matched feature points to estimate a candidate homography matrix. Then, I project all feature points from the left image to the right image using this matrix and measure their reprojection errors. Points with errors smaller than a certain threshold (e.g., 3 pixels) are considered inliers. I repeat this process for many random samples (around 2000 iterations) and keep the homography that yields the largest number of inliers. Finally, I recompute the homography using all inlier correspondences judged by the best homography matrix to obtain a more accurate and robust result.
